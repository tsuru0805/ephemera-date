# 写约会那一轮的思考：遮住与揭开

约会内容在公开时间之前不该让她看到。她那侧的接口只返回投影（见 [API.md](API.md)），但 AI 写约会的那段对话不经过引擎：工具回执里有完整行程，AI 的思考里也有。引擎管不到任何聊天界面，所以这一部分由**自建网关**（你自己在 AI 和她的聊天页之间转发消息的服务）来做。本文说明规则和接法，参考实现是 `src/ephemera_date/seal.py`（纯函数，不读写任何东西），测试在 `tests/test_seal.py`。

## 1. 规则

一轮对话（她发一条、AI 回一条，中间可能有多次工具调用）满足下面任一条，就**盖住**这一轮的思考：

1. 这一轮调用过任一约会工具，包括调用失败的。盖的是整轮，包括调用之前那段思考。
2. 这一轮是被约会叫醒的：AI 收到的那条消息是引擎的到点提醒或「请他补写」，正文以 `[约会提醒] ` 或 `[约会请写] ` 开头（`plan.REMIND_HEAD` / `plan.REQUEST_HEAD`，后面跟一个空格）。

系统提示里带着约会账（`GET /context` 的文字）**不算**，不盖。约会账不含进行中约会的名字与内容。

盖住的含义：

- 是界面上的蒙版，不是加密。数据照常存，网关和数据库能读到原文。
- 随消息存：打标写进这条消息的记录里，回放、重新打开都还是盖着的。
- 被盖那一轮的思考不进任何摘要（对话摘要、压缩、记忆提取）；思考标题（如果网关会给思考生成标题）只在揭开之后显示，没揭开时不显示、不生成也可以。
- 她确认之后可以揭开。揭开是她在界面上的动作（例如点开时先弹一句确认），网关记录「这一轮已揭开」，之后照常显示。

## 2. 哪些工具算

`seal.SEAL_TOOLS`：

| 工具 | 算不算 | 理由 |
|---|---|---|
| `date_open`、`date_view`、`date_edit`、`date_send`、`date_live`、`date_close` | 算 | 写或显示站、地点、线索、路段和她还没看到的文字 |
| `date_route` | 算 | 查两地之间的步行时间，用在挑站的时候；地点本身就是要保密的内容 |
| `date_inbox` | 算 | 列出进行中约会的待办：提醒里的站号与时刻，「请他补写」里的约会名和日期；处理待办的那一轮就是在写这次约会 |
| `date_memory` | 不算 | 只查已经结束的约会。约会结束时全部内容对她公开（工具结果的 `ephemera/reveal_after` 有值），查出来的东西她都已经能看到。想一并盖住的网关传 `seal_memory=True` |

MCP 客户端常给工具名加前缀（例如 `mcp__ephemera__date_edit`）。`seal.bare_tool_name` 取最后一个 `__` 之后的部分再比较。引擎以后新增工具时，`tests/test_seal.py::test_every_engine_tool_is_classified` 会失败，提醒先归类。

## 3. 网关怎么接

```python
from ephemera_date import seal

# 一轮开始：她发来的（或引擎叫醒时发来的）那条消息
sealed = seal.should_seal([], wake_text=user_message_text)
if sealed:
    db.mark_sealed(message_id)                 # 落库：随消息存
    push_to_page({"event": "date_sealed", "message_id": message_id})

# 流式过程中：每见到一个工具调用（tool_use 事件），不论之后成败
calls.append(event)                          # event = {"name": "...", ...} 或工具名字符串
if not sealed and seal.should_seal(calls):
    sealed = True
    db.mark_sealed(message_id)                 # 只置位，不撤销
    push_to_page({"event": "date_sealed", "message_id": message_id})

# 生成摘要、压缩、思考标题之前
turn_for_summary = seal.redact_for_summary({"sealed": sealed, "thinking": ..., "thinking_title": ...,
                                            "content": blocks})
```

要点：

- **从轮开始就判一次**（第 2 条，叫醒轮），**每见到一个工具调用再判一次**（第 1 条）。工具调用可能出现在思考之后，所以打标要能「补盖」整轮：前端收到 `date_sealed` 时，把这一轮已经显示的思考也盖上。
- **打标只置位不撤销**：同一轮里后面没有约会工具，不会让前面的打标失效。揭开是另一个字段（她的确认），不要复用打标字段。
- **前端**：读消息时带上打标与揭开两个状态；盖着的轮把思考区换成一块不透明的蒙版（例如「这一轮在写约会」），点开先确认再显示。思考标题同样只在揭开后显示。
- **其他出口**：凡是没有蒙版可用的出口（消息列表的预览、活动记录、导出、给别的模型看的上下文摘要），对盖着的轮直接不给思考与思考标题，用 `redact_for_summary` 的结果。
- **重新生成**：重新生成一轮时，按被重答的那条消息原文判第 2 条，不要按「重新生成」这个动作本身的文字。
- **叫醒正文**：引擎发给 AI 的叫醒文字都带固定开头——AI 待办的文字、AI 待办 webhook 请求体的 `text`（`EPHEMERA_AI_WEBHOOK`，见 [使用指南「AI 待办：三条路」](GUIDE.md#ai-待办三条路)）。网关把它作为这一轮的用户消息发给 AI 时，原样保留开头，`is_date_wake` 才认得出来。约会账（`/context`）里的待办列表也会出现 `[约会提醒]` 字样，但不在开头，不会被当成叫醒。

## 4. 与工具结果 `_meta` 的关系

引擎给每个工具结果带机器可读的保密标记（MCP 结果的 `_meta`，见 [使用指南「保密在 AI 一侧」](GUIDE.md#保密在-ai-一侧)）：

- `ephemera/secret: true`：这条结果可能含她现在不该看到的内容。网关显示工具结果时据此遮住结果本身。
- `ephemera/reveal_after`：从这个时刻（epoch 秒）起结果全部可以公开，即约会已结束；`null`=还不知道，继续遮。
- `ephemera/plan_ids`：结果涉及哪几次约会。

两者分工：`_meta` 管**工具结果**这一块；本文的打标管**这一轮的思考**（以及思考标题、摘要）。一轮被盖住时，这一轮的工具结果按 `_meta` 照样遮。`reveal_after` 可以用来提示「这一轮涉及的约会已经结束，可以揭开了」，但揭开仍要她确认，不自动揭开。

## 5. 现成客户端遮不住

claude.ai 网页、Claude Desktop 等现成的 MCP 客户端会忽略 `_meta`，也没有「盖住思考」这一功能：工具回执和思考都会照常显示在对话里。用这些客户端写约会时，唯一的办法是**单独开一个她看不到的对话**写约会，不要在她也会看的对话里调用约会工具。只有自建网关（自己控制存储与前端）才能按本文的规则遮住。
